# Looply — 환경영향 데이터 분석 및 AI 해설 사례 연구

## 한눈에 보기
- **목적:** 공개 환경영향 평가계수를 정제하고 일반인도 이해할 수 있는 인터랙티브 데이터 보고서로 구현
- **데이터:** 한국환경산업기술원 환경성적표지 평가계수(2021-08-02 자료 기반 정제본), 398개 항목, 5개 영향범주
- **역할:** 개인 포트폴리오. 데이터 전처리, 분석 설계, 프론트엔드 시각화, AI API 연동 및 테스트 구성
- **기술:** Python, Pandas, NumPy, JavaScript, Plotly.js, KMeans, FastAPI, OpenAI API, GitHub Actions, GitHub Pages, Render
- **시연:** [AI 개발 버전](https://looply-ai-preview.onrender.com/) / [기존 안정 버전](https://goalbangg-prog.github.io/Looply-mini-LCA/)
- **저장소 상태:** AI 개발 브랜치 `feature/ai-insights`. `main` 병합 보류

## 1. 해결하고자 한 문제
환경영향 평가계수는 항목마다 기준 단위와 값의 유효 여부가 달라, 숫자만 나열하면 잘못된 비교가 발생하기 쉽습니다. 특히 개별 평가계수를 제품 전체의 LCA 결과처럼 이해하거나 결측값을 0으로 취급하는 오류를 예방하고자 했습니다. 일반 사용자도 데이터를 직접 탐색하면서 해석상의 주의점을 알 수 있는 웹앱을 목표로 했습니다.

## 2. 데이터 처리 및 분석
원자료를 Python/Pandas로 정리해 `data/lca_factors_clean.csv`와 웹 데이터 파일 `lca_data.js`로 연결했습니다. 환경영향범주 다섯 가지(탄소발자국, 자원발자국, 산성화, 부영양화, 물발자국)를 다루며, 계수 기준 단위의 호환성과 결측 여부를 분석 조건에 반영했습니다.

- 분석 리포트: 데이터 범위와 분포, 영향범주 관계, 분석 한계 설명
- 환경영향 계산: 입력량을 기준 단위에 맞춰 환산한 뒤 해당 계수와 곱하는 부분 계산 및 CSV 내보내기
- 데이터 인사이트: 로그 분포, 박스플롯, 산점도, Spearman 순위상관 등
- 군집 분석: 유효 양수값의 로그 변환·표준화 후 KMeans 군집화와 실루엣 기반 탐색

**해석 예시:** 전체 398개 중 원료 및 에너지 생산 198개, 수송 10개입니다. 수송 데이터의 *개수가 적다*는 사실만으로 자료가 *부족하다*고 단정하지 않았습니다. 동일 기준 단위 시멘트 사례에서 고로 슬래그 시멘트의 탄소발자국 평가계수가 1종 포틀랜드 시멘트보다 약 45.6% 낮지만, 이는 두 제품의 전체 환경성 우열을 의미하지 않습니다.

## 3. AI 기능과 문제 해결 과정
초기 AI는 시멘트 평가계수 차이를 '전체 환경영향이 더 많다'고 표현하거나, 수송 항목 수가 적다는 이유로 '데이터가 부족하다'고 단정했습니다. 숫자 검증만으로는 이런 해석 오류를 막기 어렵다는 문제를 확인했습니다.

이를 해결하기 위해 **검증된 사실과 생성형 AI의 역할을 분리**했습니다.

1. Python `api/insight_policy.py`에서 출처 기반 수치와 핵심 주의사항을 결정적으로 생성
2. AI는 일반인을 위한 쉬운 의미 설명에 집중
3. AI가 새 숫자를 쓰거나 알려진 위험 표현을 사용하면 기본 해설로 대체
4. API 응답의 `generation`으로 AI 설명과 기본 해설을 구분
5. 네 가지 분석 화면에 AI 해설 패널을 제공하고 API 오류 시 로컬 안내문을 표시

현재 AI 설명은 화면의 사용자가 선택한 개별 계산값이나 군집 결과를 자동 해석하지 않습니다. 주제별 설명에 초점을 둔 MVP이며, 위험 표현 필터가 모든 의미 오류를 차단한다고 주장하지 않습니다.

## 4. 검증과 결과
2026-10-16 제공된 GitHub Actions 로그 기준 최신 커밋 `8a43ac0`에서 **Python 자동 테스트 12개 모두 통과**했습니다. 정상 API 응답, 잘못된 요청, 캐시 및 제한 동작, AI 제공자 장애, 검증 실패 시 대체, 시멘트·데이터 분포의 실제 오류 사례를 회귀 테스트에 포함했습니다.

개발자는 Render 최신 배포 완료 및 네 화면의 AI 해설과 기존 차트 정상 작동을 확인했습니다. 이는 기능 수준의 검증이며, 모든 입력 조합·모바일 실기기·생성 문장 전체에 대한 완전한 품질 보증은 아닙니다.

## 5. 실무 연결 및 한계
이 프로젝트는 **환경영향계수 데이터 정제 → 단위와 결측 검토 → 탐색적 분석 → 결과 시각화 → 설명 오류 방어**라는 데이터 품질관리 과정을 보여줍니다. 온실가스·LCA 컨설팅에서 필요한 데이터 검토 습관과 결과 전달 역량을 학습한 사례입니다.

그러나 실제 제품의 기능단위, 시스템 경계, LCI, 배분, 대표성, 데이터 품질 평가 등을 갖춘 완전한 LCA를 수행한 프로젝트는 아닙니다. PCF 산정이나 EPD 인증 수행 경력으로 표현하지 않습니다. 브라우저의 KMeans와 Python scikit-learn 구현이 완전히 동일한 결과를 낸다고도 주장하지 않습니다.

## 6. 면접에서 설명할 핵심
**왜 만들었나요?** 환경영향 데이터를 숫자만 보여주면 잘못 해석할 수 있어, 분석 결과와 해석상의 한계를 함께 보여주는 도구를 만들었습니다.

**가장 어려웠던 점은?** AI가 맞는 숫자를 사용하면서도 과도한 환경성 결론을 내렸습니다. 그래서 숫자뿐 아니라 문장의 역할도 분리하고, 재현 가능한 오류를 자동 테스트로 만들었습니다.

**무엇을 배웠나요?** 환경 데이터는 계산 정확성만큼 단위·결측·비교 가능성·설명 책임이 중요하며, 생성형 AI를 사용할 때도 검증된 근거와 생성 문장을 분리해야 한다는 점입니다.

**다음 개선은?** 사용자별 계산 결과에 연결되는 설명, 더 체계적인 의미 검증, 단위별 테스트 확대, 모바일 접근성 점검입니다.
